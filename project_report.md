# 📋 Підсумковий звіт по проєкту «AI Body Analyzer»

---

## 1. Загальний опис

**AI Body Analyzer** — повнофункціональний веб-застосунок для автоматичного аналізу фізичної форми людини за фотографією з використанням комп'ютерного зору (MediaPipe Pose) та штучного інтелекту (Google Gemini API).

| Параметр | Значення |
|----------|----------|
| **Frontend** | Next.js 15, TypeScript, Vanilla CSS (Glassmorphism Design) |
| **Backend** | Python 3.11+, FastAPI, SQLAlchemy 2.0 (Async) |
| **CV Engine** | MediaPipe Pose Landmarker + OpenCV |
| **AI** | Google Gemini API (ротація ключів, fallback) |
| **БД** | SQLite (dev) / PostgreSQL 16 (prod) |
| **Інфраструктура** | Docker Compose, run.bat |

## 3. Функціональні модулі та де робити скріншоти

---

### 3.1. 🔐 Авторизація та реєстрація

#### Реєстрація (`POST /api/auth/register`)
- Створення акаунта (ім'я, email, пароль)
- Хешування пароля через bcrypt
- Автоматична відправка листа верифікації email через Gmail SMTP
- Повертає JWT access + refresh токени

**(📸 Скріншот: сторінка реєстрації → `http://localhost:3000/auth/register` — форма з полями ім'я, email, пароль, підтвердження пароля)**

#### Вхід (`POST /api/auth/login`)
- Аутентифікація за email/паролем
- Перевірка хешу пароля (bcrypt)
- Повертає JWT токени + статус верифікації email

**(📸 Скріншот: сторінка входу → `http://localhost:3000/auth/login` — форма з полями email і пароль)**

#### Оновлення токена (`POST /api/auth/refresh`)
- Автоматичне оновлення access token за допомогою refresh token
- Прозорий auto-refresh на фронтенді (401 → спроба refresh → повтор запиту)

#### Верифікація email (`GET /api/auth/verify-email`)
- Перехід за посиланням з листа
- Декодування JWT токена верифікації (тип `email_verify`, TTL = 24 год)
- Оновлення статусу `email_verified` в БД

**(📸 Скріншот: сторінка очікування верифікації → `http://localhost:3000/auth/verify-pending` — показує що лист надіслано, кнопка "Надіслати повторно" з cooldown 60 сек)**

**(📸 Скріншот: сторінка підтвердження email → `http://localhost:3000/auth/verify-email?token=...` — показує статус: успішно / вже підтверджено / помилка)**

**(📸 Скріншот: лист у Gmail — стилізований HTML email з кнопкою "Підтвердити email")**

#### Повторна відправка (`POST /api/auth/resend-verification`)
- Rate-limiting: не частіше ніж раз на 60 сек
- Фонова відправка через `BackgroundTasks`

#### Перевірка статусу (`GET /api/auth/verification-status`)
- Auto-polling кожні 5 сек на сторінці verify-pending
- Автоматичний редирект після підтвердження

### 3.2. 👤 Управління профілем

#### Перегляд профілю (`GET /api/users/me`)
- Повертає: id, name, email, email_verified, avatar_url, created_at

#### Оновлення профілю (`PATCH /api/users/me`)
- Зміна імені та аватара
- Анімація збереження з тимчасовим повідомленням "Збережено"

**(📸 Скріншот: сторінка профілю → `http://localhost:3000/profile` — поле імені, кнопка "Зберегти", секція видалення акаунта)**

#### Видалення акаунта (`DELETE /api/users/me`)
- Каскадне видалення всіх даних (images, analyses, chat_messages)
- Двоетапне підтвердження видалення на фронтенді
- Redirect на логін після видалення

**(📸 Скріншот: діалог підтвердження видалення акаунта на сторінці профілю)**

### 3.3. 📸 Завантаження фото

#### Завантаження (`POST /api/images`)
- Drag-and-drop або вибір файлу
- Обмеження: тільки JPG/PNG, до 10 МБ
- Збереження оригіналу + автоматична генерація мініатюри (256×256 px, Pillow)
- Файли зберігаються у `uploads/<user_id>/`

**(📸 Скріншот: головна сторінка до завантаження → `http://localhost:3000` — drag-and-drop зона з текстом "Перетягніть фото сюди" + поля Зріст/Вага)**

**(📸 Скріншот: головна сторінка з прев'ю обраного фото перед аналізом)**

#### Список фото (`GET /api/images`)
- Всі фото поточного користувача, відсортовані за датою

#### Видалення фото (`DELETE /api/images/{id}`)
- Видалення файлів з диску + запису з БД
- Каскадне видалення аналізу

### 3.4. 🦴 Аналіз фізичної форми

#### Запуск аналізу (`POST /api/analysis`)
**Етап 1 — CV аналіз (MediaPipe Pose):**
- Визначення 33 ключових точок тіла (keypoints)
- Розрахунок пропорцій: плечі/талія, симетрія рук/ніг, довжина тулуба
- Оцінка постави: нахил плечей, нахил тазу, вирівнювання голови
- Виявлення слабких зон (shoulders_back, legs_glutes, arms, posture_*)
- Генерація анотованого зображення (з лініями скелету)

**Етап 2 — AI аналіз (Google Gemini):**
- Мультимодальний аналіз фото + пропорцій через Gemini API
- Визначення: тип тілобудови, % жиру, оцінка сухості, оцінка м'язової маси
- Оцінка 6 м'язових груп (плечі, груди, спина, руки, кор, ноги) — score 0-10 + опис
- Корекція координат keypoints AI-моделлю (corrected_keypoints)
- Визначення типу фото (full_body / torso_only)
- Загальний рейтинг (overall_rating) за формулою

**Етап 3 — Генерація рекомендацій:**
- На основі слабких зон автоматичний підбір вправ
- База вправ з пріоритетами (м'язова група, опис, кількість підходів)

**(📸 Скріншот: процес аналізу на головній сторінці — прогрес-бар + повідомлення етапу + міні-гра TicTacToe під час очікування)**

**(📸 Скріншот: результат аналізу на головній сторінці — карточки з метриками: пропорції, постава, слабкі зони)**

#### Денний ліміт сканувань (`GET /api/analysis/scan-limit`)
- Ліміт: 3 скани на день (UTC)
- Показує: used, limit, remaining, resets_in_seconds

**(📸 Скріншот: індикатор ліміту сканувань на головній сторінці — "Залишилось X/3 сканувань")**

#### Деталі аналізу (`GET /api/analysis/{id}`)
- Повна інформація: keypoints, proportions, posture, weak_zones, gemini_analysis, recommendations
- Анотоване зображення з точками скелету

**(📸 Скріншот: сторінка деталей аналізу → `http://localhost:3000/analysis/[id]` — загальний вигляд з рейтингом, типом тілобудови)**

**(📸 Скріншот: секція "Пропорції тіла" на сторінці деталей — waist/shoulder ratio, torso/leg ratio)**

**(📸 Скріншот: секція "М'язові групи" — оцінки 6 груп з кольоровими прогрес-барами і описами)**

**(📸 Скріншот: секція "Постава" — нахил плечей, тазу, вирівнювання голови)**

**(📸 Скріншот: секція "Слабкі зони" — список зон з severity: low/moderate/high)**

**(📸 Скріншот: секція "Рекомендації" — вправи з описом, підходами, пріоритетом)**

**(📸 Скріншот: анотоване зображення — фото з нанесеними точками скелету і лініями)**

#### Інтерактивна корекція координат (`POST /api/analysis/{id}/recalculate`)
- Drag-and-drop переміщення точок скелету на фото
- Live-перерахунок пропорцій при переміщенні
- Повторний запуск CV аналізу з новими координатами
- Оновлення рейтингу та рекомендацій

**(📸 Скріншот: режим редагування координат — точки скелету з маркерами для drag, зміна кольору активної точки)**

**(📸 Скріншот: до і після перетягування координат — зміна значень пропорцій)**

#### Оновлення метрик (`PATCH /api/analysis/{id}/metrics`)
- Введення зросту (см) та ваги (кг) після аналізу
- Перерахунок % жиру за BMI формулою з коригуванням на м'язову масу
- Перерахунок dryness_score та overall_rating

**(📸 Скріншот: форма введення зросту/ваги на сторінці деталей аналізу)**

#### Список аналізів (`GET /api/analysis`)
- Легковагі саммарі для дашборду (без keypoints)

### 3.6. 🤖 AI-асистент (Чат)

#### Звичайний чат (`POST /api/assistant/chat`)
- Відправка повідомлення → отримання повної відповіді
- Контекст: ім'я користувача + дані аналізу + останні 8 повідомлень
- Збереження і user message, і assistant reply в БД

#### Streaming чат (`POST /api/assistant/chat/stream`)
- Посимвольне отримання відповіді через `StreamingResponse`
- Друк тексту в реальному часі (typewriter effect)
- Збереження повної відповіді в БД після завершення стриму

#### Контекст аналізу
- Можливість прив'язати чат до конкретного аналізу (`analysis_id`)
- AI отримує дані пропорцій, постави, слабких зон, Gemini аналізу
- Можливість вибрати аналіз із випадаючого списку

#### Системний промпт
- Роль: AI-тренер, мотиватор
- Обмеження: не дає медичних діагнозів
- Мова: українська за замовчуванням
- Пояснення метрик, рекомендації вправ/харчування

#### Fallback режим
- Коли немає API ключа — rule-based відповіді
- Базові пояснення метрик та рекомендації

**(📸 Скріншот: чат з AI-асистентом → `http://localhost:3000/assistant` — повідомлення користувача + відповідь AI з markdown-форматуванням)**

**(📸 Скріншот: вибір контексту аналізу в чаті — dropdown зі списком попередніх аналізів)**

**(📸 Скріншот: streaming відповідь — текст друкується посимвольно)**

#### Історія чату (`GET /api/assistant/history`)
- Останні 50 повідомлень (ліміт до 100)
- Фільтрація за analysis_id або загальний чат

### 3.8. 🔒 Безпека

| Механізм | Реалізація |
|----------|------------|
| Хешування паролів | bcrypt (salt + hash) |
| Access Token | JWT HS256, TTL = 30 хв |
| Refresh Token | JWT HS256, TTL = 7 днів |
| Email Verify Token | JWT HS256, TTL = 24 год |
| Auth Guard (backend) | FastAPI Depends — `get_current_user`, `get_verified_user` |
| Auth Guard (frontend) | `<AuthGuard>` компонент — redirect на login/verify-pending |
| Rate Limiting | Resend verification: 60 сек cooldown; Scan limit: 3/день |
| CORS | Конфігурується через `CORS_ORIGINS` |
| Auto-refresh | 401 → автоматичне оновлення access token через refresh |

## 4. Діаграма прецедентів (Use Case)

### Актори:

| Актор | Опис |
|-------|------|
| **Гість** | Неавторизований відвідувач. Може реєструватися та входити в систему |
| **Користувач** | Авторизований користувач (email може бути не верифікований). Управляє профілем |
| **Верифікований користувач** | Користувач з підтвердженим email. Має повний доступ до функціоналу |
| **Система** | Внутрішні сервіси (CV Engine, AI, Email) |

### Прецеденти:

**Автентифікація (Гість):**
- Реєстрація → `<<include>>` Відправка email верифікації
- Вхід у систему

**Управління профілем (Користувач):**
- Перегляд профілю
- Редагування профілю
- Видалення акаунта
- Вихід із системи

**Аналіз тіла (Верифікований користувач):**
- Завантаження фото
- Видалення фото
- Запуск аналізу тіла → `<<include>>` CV аналіз (MediaPipe) → `<<include>>` AI аналіз (Gemini) → `<<include>>` Генерація рекомендацій
- Перегляд результатів аналізу
- Корекція координат скелету
- Введення зросту та ваги
- Перегляд дашборду

**AI-асистент (Верифікований користувач):**
- Чат з AI-асистентом
- Перегляд історії чату

## 7. Запуск проєкту

### Найпростіший спосіб — `run.bat`:
1. Перевіряє наявність Python та Node.js
2. Створює Python venv + встановлює залежності
3. Встановлює npm залежності
4. Запускає backend (`:8000`) та frontend (`:3000`) в окремих вікнах
5. Відкриває браузер на `http://localhost:3000`

**(📸 Скріншот: вивід run.bat в консолі — повідомлення про запуск сервісів)**

### Docker Compose:
```bash
docker-compose up --build
```
Контейнери: PostgreSQL 16 + Backend + Frontend

**(📸 Скріншот: Swagger API Docs → `http://localhost:8000/docs` — автогенерована документація FastAPI)**

## 10. Додаткові особливості

- **Ротація API ключів** — підтримка кількох Gemini ключів через `gemini_keys.txt` з автоматичним fallback
- **Fallback моделі** — при помилці `gemini-3.5-flash` автоматично пробує `gemini-3.1-flash-lite`
- **Адаптивний дизайн** — Glassmorphism UI, dark theme, анімації входу (`animate-in`)
- **Пасхалка** — міні-гра TicTacToe з'являється під час довгого аналізу
- **Каскадне видалення** — видалення юзера → видаляються всі фото, аналізи, чати
- **Auto-create tables** — при старті бекенду таблиці створюються автоматично (dev mode)
- **Alembic міграції** — підготовлена структура для production міграцій
